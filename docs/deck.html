01 · The constraint · UIT-VSFC

One class is 4% of the corpus

0.8629accuracy
0.7149macro-F1

Accuracy is carried by the two large classes. Macro-F1 weights neutral equally with them — so a model can look 86% right and be poor at a third of the label space.

consequence 1

The balance rule is a per-class floor, not a deviation from a 0.5 prior. A prior only exists for a balanced binary problem.

consequence 2

The tuning objective is cross-validated. One split can move macro-F1 by points on 458 rows alone.

consequence 3

The original macro-F1 ≥ 0.92 target — written for balanced binary English — was replaced with one that is reachable and justified.

1:00. The most important data slide. If they remember one number from your section, it is 4%. The three cards are the payoff — say “three decisions trace back to this”.

04 · Deep dive · gate one

The gate fails the run, it does not warn

CheckRejectsThreshold
schemaa missing label or text columnexact

why 2% and not a prior

The rule used to be “positive ratio within 0.1 of 0.5” — correct for balanced binary, guaranteed to fail every healthy run here. 2% sits under the observed 4.0 / 4.6 / 5.3% and far above zero.

it was broken, and we found it

Training used to call load_dataset() directly, so this gate guarded data nobody trained on. Training now has one entrance, and a Settings validator raises if the data and training layers ever name different datasets.

$ python scripts/train_model.py
train 11426 rows · classes [0,1,2] · rarest 0.0401
validation 1583 rows · rarest 0.0461
test 3166 rows · rarest 0.0527
sha256 006759bf5ccc43dc… → logged to MLflow

The fingerprint is over the rows in order, with delimiters — so reordering changes it, and two different datasets that concatenate to the same bytes do not collide. Both have tests.

It answers a question you otherwise cannot: did these two runs see the same data?

1:00. “Fails the run” is the phrase, not “validates”. If asked why not DVC: the dataset is immutable on the hub — we needed provenance, not remote storage.

06 · Deep dive · experiments

The search did real work

best trial 0
ngram_range (1,2)
max_features 5000
C 0.964
class_weight balanced ← rediscovered

The sweep independently chose to weight the minority class. Nobody told it about the 4%.

the expensive choice

The objective is cross-validated, not a single held-out score. That is 3× the compute — and the only reason the ranking means anything. On one split, the trial that drew the favourable fold wins and its configuration does not reproduce.

what MLflow holds

18 runs. Each trial is a nested run under one parent, carrying its params, its cross-validated score, the dataset fingerprint, SHAP importance charts and a fairness report.

1:00. If asked about the transformer: implemented, contract-tested by the slow suite, not promoted. Say it before they ask — slide 4 already flagged it.
07 · Deep dive · gate two

Promotion is a rule, not a decision

CheckThresholdMeasuredWhat it protects against

rollback

A stage transition plus a reload. No rebuild, no redeploy — which is what makes it safe enough to do under pressure at 3am.

The gate caught a bug that code review did not.

train blind_identity=True → 0.000000
save joblib.dump(pipeline) ← flag lost
load blind_identity=False → 0.079990
gate FAIL — refused to promote

A model trained with identity blinding lost the flag when it was reloaded from joblib, and kept predicting — on text it had never been fitted on. Textbook train/serve skew, and it ships silently almost everywhere.

It was caught because the gate re-measures the loaded artifact rather than trusting the number training reported. The flag now travels inside the artifact, and a regression test fails if it ever stops.

1:15. The best story in the deck — tell it slowly. The transferable point: measure the thing you will deploy, not the thing you trained.
08 · Deep dive · serving under load

Three exits, and none of them block the loop

429, not 503

429 says “retry shortly” — a full pool is the service working as designed. 503 is what /ready returns when no model is loaded. Two different facts deserve two different codes.

/health stays 200

If a model fault turned liveness red, the orchestrator would restart the container in a loop while you diagnosed it — and you would lose the logs each time. The Docker HEALTHCHECK targets /ready, so a broken release is still not marked healthy.

1:15. The densest slide — walk left to right, then down. Expect “why not autoscale”: single-replica CPU is the stated target and the drift window is in-memory.

coverage was a lie, briefly

The omit list excluded data/, models/, training/ and responsible/ — so a real 91% described a quarter of the package. Narrowed to the two modules that need a GPU and a live server.

testing the instrument

The fairness probe is asserted to detect a known injected bias on the right axis and report zero for a known-fair scorer. An unchecked instrument can manufacture a result.

  • The publish job pulls the published image back and checks /ready — a broken publish fails in CI, not on someone else's machine
  • A nightly workflow runs the slow set and re-checks the fairness gate on a freshly trained model
  • Smoke tests run against the real Compose stack, not a mock

ci was stricter than our own command

The workflow hand-listed mypy and the type stubs while requirements-dev.txt pinned a different stubs version — so make typecheck passed locally and the build failed.

Two places pinning one toolchain is the bug. CI now installs from requirements-dev.txt, and the drift cannot recur.

0:45. The right-hand card is the point: we treat the toolchain as part of the system, not as somebody's laptop setup.
13 · Responsible AI · the measurement

Two sentences, one word apart

UIT-VSFC has no demographic columns — group-wise accuracy is impossible, because there is nobody to group by. So the probe interrogates the model, over HTTP against the deployed service, covering the real preprocessing and the real checkpoint.

The score compared is the continuous output, not the argmax label. Two sentences can share a label while the model is visibly less positive about one of them.

the mitigation that failed

Counterfactual augmentation cut gender bias 79% and still failed the gate — region became the binding constraint at 0.1080.

why, measurably

Region terms appear 0 times in training data; thầy and cô appear in 23.9% and 11.1% of rows. Augmentation cannot teach words the model never saw.

what worked, and its cost

Blinding removes the terms before vectorising — exactly zero by construction. Cost: +0.0006 macro-F1. Free, which is itself the finding.

1:45 — the highest-value slide. Do not rush. Then the admission: our first measurement said 0.63, because the probe used capitalised Thầy against an entirely lowercase corpus. It was measuring casing, not bias.

→ negative
live, /api/v1/explain

LIME · local, live

Which tokens moved this decision. Rebuilt whenever a reload changes the model, so an explanation never describes a model that is no longer answering.

SHAP · global, offline

What the model relies on overall. Logged as an MLflow artifact per training run, with a chart per class.

what this system refuses to be used for

Evaluating an individual lecturer. A per-teacher score from a model with a measured identity gap, on sarcasm it cannot read, is a number that looks objective and is not — and employment consequences from it would be indefensible. This is aggregate triage, and docs/ETHICS.md says so before anyone asks.

Stated limitation. The Predictor protocol exposes one positive-class score, so LIME explains the positive-class probability rather than attributing across all three classes.

0:45. The refusal is the part that scores. Anyone can add SHAP; naming the use you decline is what “thoughtful ethics” means.
